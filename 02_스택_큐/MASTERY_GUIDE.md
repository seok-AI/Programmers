# 스택/큐 마스터 가이드

## 이 유형의 본질

스택과 큐는 저장 공간이 아니라 **처리 순서에 제약을 부여하는 모델**이다.

- 스택: 가장 최근에 열린 일, 아직 짝을 찾지 못한 후보, 이전보다 가까운 원소
- 큐: 먼저 도착한 일, 시간 순 이벤트, 같은 깊이의 탐색 대상

마스터는 문제의 서술에서 “다음에 꺼내야 할 대상”을 알아보고 LIFO인지 FIFO인지
설명한다. 단조 스택처럼 스택 안에 추가 순서 조건을 유지할 수 있어야 한다.

## 문제에서 포착할 신호

- 괄호, 되돌리기, 최근 패턴, 연속 제거
- 먼저 들어온 순서대로 처리하되 조건에 따라 뒤로 보냄
- 초/날짜별로 대기열이 이동함
- 각 원소의 오른쪽/왼쪽에서 처음 만나는 더 크거나 작은 값
- 앞 작업 때문에 뒤 작업이 대기함
- 단순 이중 반복으로 각 원소의 미래를 찾으면 `O(n^2)`가 됨

## 사고 절차

1. 원소가 들어오는 순서를 정의한다.
2. 꺼낼 수 있는 위치가 한쪽인지 양쪽인지 확인한다.
3. 컨테이너 안 원소가 의미하는 바를 문장으로 쓴다.
4. 원소 하나가 최대 몇 번 들어가고 나오는지 세어 복잡도를 증명한다.
5. 시간 시뮬레이션이라면 매초 진행할지, 다음 이벤트 시각으로 점프할지 결정한다.

## 핵심 불변식

- 괄호 스택: 스택에는 아직 닫히지 않은 여는 괄호만 있다.
- 패턴 제거 스택: 스택에는 지금까지 들어왔지만 완성 패턴으로 제거되지 않은 재료만 있다.
- 단조 스택: 스택의 값 또는 인덱스가 단조 순서를 유지한다.
- 큐 시뮬레이션: 큐의 왼쪽은 현재 규칙상 다음으로 검토할 대상이다.
- 다리/프로세스: 큐의 순서는 실제 대기 순서와 동일하다.

## 구현 패턴

### 괄호와 최근 상태

```python
stack = []
for token in tokens:
    if is_open(token):
        stack.append(token)
    else:
        if not stack or not matches(stack[-1], token):
            return False
        stack.pop()
return not stack
```

### 큐

```python
from collections import deque

queue = deque(initial)
while queue:
    current = queue.popleft()
    if should_delay(current):
        queue.append(current)
    else:
        process(current)
```

### 다음으로 작은 값을 찾는 단조 스택

```python
stack = []  # 아직 답을 못 찾은 인덱스, 값은 단조 증가
answer = [default] * len(values)

for i, value in enumerate(values):
    while stack and values[stack[-1]] > value:
        j = stack.pop()
        answer[j] = i - j
    stack.append(i)
```

각 인덱스는 한 번 push, 한 번 pop되므로 중첩 `while`이 있어도 전체 `O(n)`이다.

## 이 폴더의 추천 학습 순서

1. `01_12906_같은_숫자는_싫어`: 이전 상태 한 개와 스택적 사고를 익힌다.
2. `02_12909_올바른_괄호`: 접두 구간 불변식을 익힌다.
3. `03_133502_햄버거_만들기`: 최근 네 원소 패턴 제거를 스택으로 모델링한다.
4. `04_42586_기능개발`: 완료 시각 계산 후 배포 그룹을 큐처럼 묶는다.
5. `05_42587_프로세스`: 순환 큐와 우선순위를 결합한다.
6. `06_42583_다리를_지나는_트럭`: 시간, 길이, 무게 상태를 동시에 관리한다.
7. `07_42584_주식가격`: 이중 반복을 단조 스택으로 최적화한다.

`주식가격`은 단순 이중 반복도 제한에 따라 통과 가능할 수 있지만, 반드시 단조 스택
버전을 추가로 작성해 각 원소가 두 번만 처리되는 이유를 설명한다.

## 자주 틀리는 이유

- 리스트의 `pop(0)`을 사용해 전체가 `O(n^2)`가 된다.
- 큐의 길이를 반복문 도중 바꾸면서 같은 라운드 범위를 잃는다.
- 스택에 값만 넣고 답 계산에 필요한 인덱스를 잃는다.
- 마지막까지 pop되지 않은 원소의 답을 처리하지 않는다.
- 시간 0, 진입 시각, 탈출 시각을 한 칸씩 어긋나게 센다.
- 패턴 제거 후 새로 이어진 경계에서 또 패턴이 생기는 경우를 놓친다.

## 디버깅 방법

시간 문제는 다음 표를 직접 만든다.

```text
시각 | 새로 들어옴 | 처리 중/컨테이너 | 나감 | 누적 답
```

단조 스택은 매 반복 직후 스택의 인덱스와 대응 값을 출력해 단조성이 깨지는 최초
시점을 찾는다. 전체 큰 예제를 보지 말고 길이 2~5의 최소 반례를 쓴다.

## 효율적인 훈련법

- 같은 문제를 “직접 시뮬레이션”과 “이벤트 시각 계산” 두 방식으로 푼다.
- 단조 스택 문제는 느린 `O(n^2)` 기준 풀이를 만들고 무작위 작은 배열로 비교한다.
- 괄호 문제를 한 종류 → 여러 종류 → 와일드카드 포함 순으로 확장한다.
- 큐 문제에서 컨테이너 안 튜플 필드를 최소화해 상태 설계 능력을 기른다.

### 확장 문제 주제

- 괄호 유효성·후위 표기식
- 일일 온도·오큰수·히스토그램

- 작업 스케줄링과 라운드 로빈
