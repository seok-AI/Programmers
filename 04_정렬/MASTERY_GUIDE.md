# 정렬 마스터 가이드

## 이 유형의 본질

정렬은 답을 직접 만드는 연산보다 **복잡한 관계를 이웃 관계로 바꾸는 전처리**다.
시간, 구간, 크기, 문자열을 적절한 순서로 놓으면 이전에는 모든 쌍을 비교해야 했던
문제가 한 번의 선형 순회로 바뀐다.

정렬 마스터는 오름차순/내림차순을 넘어서 “무슨 키를 어떤 우선순위로 비교해야
문제의 목적과 같아지는가?”를 설계하고 그 비교가 추이성을 갖는지 확인한다.

## 문제에서 포착할 신호

- k번째, 순위, 중앙값, 가장 큰/작은 조합
- 구간이 겹치는지, 앞뒤 원소만 비교하면 되는지
- 동률일 때 두 번째·세 번째 기준이 명시됨
- 원래 순서가 필요 없거나 원본 인덱스를 함께 보존해야 함
- 숫자를 문자열로 이어 붙이는 등 일반 숫자 순서가 아닌 비교 규칙
- 정렬 후 누적합·투 포인터·그리디·이분탐색이 가능함

## 사고 절차

1. 정렬 후 서로 가까워져야 하는 대상을 정한다.
2. 비교 키를 자연어로 “1순위, 2순위, 3순위”로 쓴다.
3. 오름/내림 방향을 필드마다 결정한다.
4. 동률이 결과에 영향을 주는지 확인한다.
5. 정렬 후 한 번의 순회에서 유지할 상태를 정의한다.
6. 원본 순서/인덱스가 필요하면 튜플에 함께 보관한다.

## Python 정렬 패턴

```python
# 1순위 score 내림차순, 2순위 name 오름차순
records.sort(key=lambda x: (-x.score, x.name))

# 원본은 유지
ordered = sorted(values, key=lambda x: (x[n], x))

# 원본 인덱스 보존
ordered = sorted(enumerate(values), key=lambda pair: pair[1])
```

Python 정렬은 안정적이다. 앞서 한 정렬의 동률 순서가 다음 안정 정렬에서 보존되지만,
가능하면 튜플 키 하나로 기준을 드러내는 편이 검증하기 쉽다.

### 사용자 비교가 필요한 경우

이어 붙인 결과를 비교할 때처럼 `a+b`와 `b+a`를 비교해야 하면 단순 문자열/숫자
정렬로는 부족하다. 비교 함수가 일관된 순서를 만드는지 확인하고 `cmp_to_key`를 쓴다.

```python
from functools import cmp_to_key

def compare(a, b):
    if a + b > b + a:
        return -1
    if a + b < b + a:
        return 1
    return 0
```

## 이 폴더의 추천 학습 순서

1. `01_12915_문자열_내_마음대로_정렬하기`: 복합 키와 안정 정렬을 익힌다.
2. `02_42748_K번째수`: 슬라이싱, 정렬, 1기반 명령을 정확히 옮긴다.
3. `03_42747_H-Index`: 정렬 후 조건이 변하는 경계를 찾는다.
4. `04_42746_가장_큰_수`: 일반적이지 않은 비교 규칙을 증명한다.

`가장 큰 수`에서는 예제 몇 개로 비교 함수를 추측하는 데서 멈추지 말고, 두 문자열
a, b에 대해 a가 앞에 와야 하는 조건이 `a+b > b+a`임을 설명한다.

## 정렬과 함께 익혀야 할 기법

- 정렬 + 투 포인터: 두 합, 짝짓기, 구간 압축
- 정렬 + 누적합: 예산, 구간 합, 순위 경계
- 정렬 + 그리디: 회의실, 구명보트, 카메라
- 정렬 + 이분탐색: 값 존재, lower/upper bound
- 정렬 + 스위프 라인: 시작/종료 이벤트 처리

## 자주 틀리는 이유

- 숫자를 문자열로 바꾼 뒤 일반 사전순으로 정렬한다.
- `reverse=True`가 튜플의 모든 필드를 뒤집는다는 점을 놓친다.
- 동률 기준을 빼먹거나 잘못된 부호를 쓴다.
- 1기반 구간을 Python 슬라이스로 옮길 때 끝 인덱스를 틀린다.
- 원본 배열을 정렬해 후속 로직이 기대하던 인덱스를 잃는다.
- 모든 값이 0인 이어 붙이기 결과를 `"000"`으로 반환한다.
