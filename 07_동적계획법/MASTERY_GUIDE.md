# 동적계획법 마스터 가이드

## 이 유형의 본질

동적계획법(DP)은 점화식을 외우는 기술이 아니라 **서로 다른 선택 이력이 미래 관점에서
동일한 상태라면 하나의 최적값으로 합치는 기술**이다. 완전탐색 트리에서 반복되는 부분
문제를 발견하고, 미래 결정에 필요한 정보만 상태로 남긴다.

DP 마스터는 상태의 의미, 초기값, 전이, 계산 순서, 정답 위치를 각각 한 문장으로
설명하고 귀납적으로 점화식이 맞음을 증명한다.

## 문제에서 포착할 신호

- 경우의 수, 최댓값, 최솟값을 요구한다.
- 선택 순서가 있고 현재 선택이 다음 선택 가능성에 영향을 준다.
- 같은 인덱스·남은 양·마지막 상태에 여러 경로로 도달한다.
- 단순 재귀가 같은 인자로 반복 호출된다.
- 원형, 구간, 격자처럼 작은 부분 문제를 합쳐 전체를 만든다.
- 그리디 선택을 증명하기 어렵고 모든 과거를 저장할 필요도 없다.

## 핵심 사고

“지금까지 어떻게 왔는가?”를 전부 기억하지 말고 “앞으로의 선택 결과를 바꾸는
정보가 무엇인가?”만 남긴다. 서로 다른 경로가 같은 최소 상태에 도달했다면 최적값,
경우의 수 또는 가능 여부로 합친다. DP의 성패는 배열 크기가 아니라 이 동치 관계를
찾는 데 달려 있다.

## 상태 설계 질문

1. 완전탐색 재귀의 인자는 무엇인가?
2. 미래 결과가 과거의 어떤 정보에만 의존하는가?
3. 그 정보가 같은 두 경로를 하나로 합쳐도 되는가?
4. `dp[state]`는 가능한가/개수/최댓값/최솟값 중 무엇인가?
5. 상태 수×상태당 전이 수가 제한 안에 드는가?

좋은 상태 정의는 문장만 읽어도 배열 값의 의미가 하나로 결정된다.

```text
dp[i] = 0..i번째까지 고려했을 때 얻을 수 있는 최대값
dp[r][c] = (r,c)에 도달하는 경로 수
dp[l][r] = l..r 구간을 계산했을 때 가능한 최적값
```

## DP 설계 5요소

### 1. 상태

미래에 필요한 최소 정보. 불필요한 전체 경로나 선택 목록을 넣지 않는다.

### 2. 초기값

실제로 가능한 가장 작은 문제를 직접 계산한다. 최솟값 DP는 무한대, 최댓값 DP는
음의 무한대가 필요할 수 있으며 0으로 초기화하면 불가능 상태가 가능한 상태가 된다.

### 3. 전이

현재 상태로 올 수 있는 직전 상태를 모두 열거한다. 최대/최소를 취할 때 후보 누락이
없는지 확인한다.

### 4. 계산 순서

전이에 필요한 상태가 먼저 계산되어야 한다. 반복형이면 인덱스 순서, 재귀형이면
메모이제이션이 이를 보장한다.

### 5. 정답

마지막 칸 하나인지, 마지막 행의 최댓값인지, 모든 상태 합인지 명시한다.

## 구현 패턴

### 1차원 최적값

```python
dp = [0] * (n + 1)
for i in range(1, n + 1):
    dp[i] = best(dp[i - 1] + take_one(i), optional_other_transition(i))
```

### 격자 경로

```python
dp = [[0] * width for _ in range(height)]
dp[0][0] = 1
for r in range(height):
    for c in range(width):
        if blocked(r, c):
            dp[r][c] = 0
            continue
        if r:
            dp[r][c] += dp[r - 1][c]
        if c:
            dp[r][c] += dp[r][c - 1]
```

### 메모이제이션

```python
from functools import lru_cache

@lru_cache(None)
def solve(state):
    if is_base(state):
        return base_value(state)
    return combine(solve(next_state) for next_state in transitions(state))
```

그려 동일한 인자 호출에 같은 색을 칠한다. 그 색이 DP 상태다.

## 점화식 증명법

`dp[i]`가 정의대로 맞다고 가정하고 `dp[i+1]`의 모든 가능한 최적해가 어느 직전 상태
중 하나에서 오는지 보인다. 반대로 전이로 만든 후보가 모두 유효함을 보이면 완전성과
안전성이 함께 증명된다.

## 자주 틀리는 이유

- 상태 정의에 “최대”인지 “정확히”인지 빠져 있다.
- 불가능 상태를 0으로 초기화해 가짜 경로가 생긴다.
- 반복문 방향 때문에 같은 항목을 여러 번 사용한다.
- 최댓값만 저장하지만 뺄셈/음수 때문에 최솟값도 필요하다.
- 원형 배열에서 첫 집과 마지막 집을 동시에 선택한다.
- 메모 키에 미래 결과를 바꾸는 정보를 누락한다.
- 모듈러 연산 시점이나 정수 나눗셈 규칙을 틀린다.

## 공간 최적화

현재 행이 이전 행에만 의존하면 두 행 또는 한 행으로 줄일 수 있다. 하지만 계산 방향이
이전 상태를 덮어쓰지 않는지 증명한 뒤 적용한다. 처음부터 공간 압축을 하면 디버깅이
어려우므로 2차원 정답 버전을 먼저 만든다.

## 효율적인 훈련법

- 모든 DP 문제에 느린 재귀를 먼저 적고 상태 중복을 표시한다.
- n≤10 무작위 입력에서 완전탐색과 DP 결과를 비교한다.
- 탑다운과 바텀업을 모두 작성해 계산 순서를 이해한다.
- 상태 정의만 보고 다른 사람이 점화식을 복원할 수 있는지 확인한다.
- 점화식, 초기값, 답 위치를 코드 주석 없이 종이에 재현한다.
