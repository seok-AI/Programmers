# 탐욕법 마스터 가이드

## 이 유형의 본질

탐욕법은 매 순간 가장 좋아 보이는 선택을 하는 기법이 아니라, **지금의 선택을 어떤
최적해에도 포함되도록 바꿀 수 있음을 증명하는 기법**이다. 정렬이나 힙은 선택을
실행하는 도구이고, 핵심은 선택의 안전성이다.

그리디 마스터는 코드보다 먼저 교환 논증, 앞선 선택 불변식, 컷 속성 중 하나로
정당성을 설명한다.

## 문제에서 포착할 신호

- 구간을 최소 개수의 점/자원으로 덮는다.
- 가장 가볍거나 무거운 대상을 짝짓는다.
- 앞자리부터 최선의 숫자를 결정한다.
- 비용이 작은 간선부터 연결한다.
- 정렬 후 한 방향으로 결정을 확정하면 되돌릴 필요가 없다.
- 부분 문제를 모두 저장하기보다 선택 하나가 미래 선택지를 지배한다.

하지만 “매번 가장 큰 값”, “가까운 것부터”는 증명 없는 직감일 뿐이다. 작은
반례를 먼저 찾아보고, 실패하면 DP나 완전탐색으로 전환한다.

## 정당성 증명 도구

### 교환 논증

임의의 최적해가 내 첫 선택과 다르다고 가정한다. 최적해의 선택을 내 선택으로
바꿔도 비용이 나빠지지 않고 이후 가능성이 유지됨을 보인다.

### 앞선 선택 불변식

i번째까지 내 알고리즘의 결과가 어떤 최적해의 접두부가 될 수 있음을 매 단계 보인다.

### 컷 속성

그래프를 두 집합으로 가르는 컷에서 가장 싼 안전 간선은 최소 신장 트리에 포함할 수
있다. Kruskal/Prim의 핵심이다.

### 지배 관계

두 상태 중 하나가 비용도 작고 미래 선택 가능성도 넓다면 다른 상태를 버린다.

## 사고 절차

1. 선택 단위를 정의한다.
2. 후보를 어떤 순서로 볼지 정렬 기준을 세운다.
3. 지금 선택을 되돌리지 않아도 되는 이유를 찾는다.
4. 반대 선택을 한 최적해를 내 선택으로 교환해 본다.
5. 교환이 실패하는 최소 반례가 있으면 그리디를 버린다.
6. 선택 후 유지할 불변식을 구현한다.

## 대표 구현 패턴

### 양끝 짝짓기

```python
values.sort()
left, right = 0, len(values) - 1
count = 0

while left <= right:
    if left < right and values[left] + values[right] <= limit:
        left += 1
    right -= 1
    count += 1
```

### 구간을 끝점으로 덮기

```python
intervals.sort(key=lambda x: x[1])
last_point = None

for start, end in intervals:
    if last_point is None or last_point < start:
        last_point = end
        answer += 1
```

### 단조 스택으로 앞자리 최적화

```python
stack = []
remaining = k
for digit in digits:
    while remaining and stack and stack[-1] < digit:
        stack.pop()
        remaining -= 1
    stack.append(digit)
if remaining:
    del stack[-remaining:]
```

## 이 폴더의 추천 학습 순서

1. `01_135808_과일_장수`: 정렬 후 높은 점수 그룹부터 구성한다.
2. `02_42862_체육복`: 중복 상태를 먼저 정리하고 이웃에게 배정한다.
3. `03_42885_구명보트`: 가장 무거운 사람의 선택을 확정하는 교환 논증을 익힌다.
4. `04_42884_단속카메라`: 구간 끝점 선택을 증명한다.
5. `05_42883_큰_수_만들기`: 접두부 최적성과 단조 스택을 결합한다.
6. `06_42860_조이스틱`: 단순 그리디가 실패하는 이동 경로를 반례로 분석한다.
7. `07_42861_섬_연결하기`: Kruskal과 Union-Find의 컷 속성을 익힌다.

`조이스틱`은 “가까운 A부터 건너뛰기” 같은 직감이 쉽게 실패한다. 모든 꺾는 위치를
검토하는 식으로 그리디와 완전탐색 경계를 학습한다.

## 자주 틀리는 이유

- 여벌과 도난 목록의 교집합을 먼저 제거하지 않는다.
- 정렬 방향은 맞지만 동률 또는 선택 시점이 틀린다.
- 무거운 사람을 혼자 태워야 할 때 포인터를 두 번 이동한다.
- 구간의 시작점에 카메라를 놓아 미래 구간을 덜 덮는다.
- 큰 수 만들기에서 남은 삭제 횟수를 뒤에서 처리하지 않는다.
- MST에서 사이클 검사를 빼거나 n-1개 간선에서 멈추지 않는다.

## 효율적인 훈련법

- 그리디 코드를 쓰기 전 3문장 증명을 강제한다.
- n≤8의 완전탐색 정답을 만들어 그리디를 랜덤 검증한다.
- 정렬 기준을 시작점/끝점/비용으로 바꿔 각각 실패하는 반례를 찾는다.
- 같은 문제를 그리디와 DP로 모두 풀어 상태가 왜 불필요해지는지 설명한다.
