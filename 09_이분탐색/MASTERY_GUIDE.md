# 이분탐색 마스터 가이드

## 이 유형의 본질

이분탐색은 정렬 배열에서 값을 찾는 코드가 아니라 **단조적인 참/거짓 경계 또는
최적 답의 경계를 로그 시간에 찾는 사고법**이다.

- 값 탐색: 정렬된 원소에서 lower/upper bound 찾기
- 답 탐색(parametric search): 답 후보 x가 가능한지 판정하는 `check(x)`를 만들기

마스터는 탐색 구간의 의미와 반복문 불변식을 정의하고, 최댓값 가능한 답과 최솟값
가능한 답의 경계 갱신을 혼동하지 않는다.

## 문제에서 포착할 신호

- 입력 값이나 정답 범위가 10억 이상이다.
- “최소 시간을 최소화”, “최소 거리의 최댓값”처럼 최적값을 묻는다.
- 어떤 기준 x를 만족하면 더 쉬운 모든 값도 만족한다.
- 직접 시뮬레이션할 수 없는 큰 시간/거리 범위를 센다.
- 정렬 배열에서 처음/마지막 위치, 개수, 삽입 위치를 구한다.

## 가장 중요한 질문: 단조성이 있는가?

`check(x)`의 결과가 다음 중 하나여야 한다.

```text
False False False | True True True   # 최소 가능한 x
True True True | False False False   # 최대 가능한 x
```

중간에 다시 바뀐다면 이분탐색할 수 없다. 샘플 몇 개가 아니라 수학적으로 단조성을
설명한다.

## 답 이분탐색 설계 절차

1. 답 후보 x의 의미와 단위를 정의한다.
2. 반드시 답을 포함하는 `[lo, hi]`를 정한다.
3. `check(x)`가 무엇을 반환하는지 한 문장으로 쓴다.
4. x가 커질 때 판정이 어느 방향으로 바뀌는지 증명한다.
5. 찾는 것이 첫 True인지 마지막 True인지 정한다.
6. 루프 종료 후 반환할 변수를 명시한다.

## 안전한 템플릿

### 조건을 만족하는 최소값

```python
lo, hi = minimum_candidate, maximum_candidate
while lo < hi:
    mid = (lo + hi) // 2
    if feasible(mid):
        hi = mid
    else:
        lo = mid + 1
return lo
```

불변식: 답은 항상 닫힌 구간 `[lo, hi]` 안에 있다.

### 조건을 만족하는 최대값

```python
lo, hi = minimum_candidate, maximum_candidate
while lo < hi:
    mid = (lo + hi + 1) // 2  # 위쪽 중간값
    if feasible(mid):
        lo = mid
    else:
        hi = mid - 1
return lo
```

위쪽 중간값을 쓰지 않으면 `lo + 1 == hi`일 때 무한 반복할 수 있다.

### 정렬 배열 경계

```python
from bisect import bisect_left, bisect_right

first = bisect_left(values, target)
after_last = bisect_right(values, target)
count = after_last - first
```

## `check` 함수 설계

판정 함수는 최적해를 직접 구성할 필요가 없다. x가 가능한지만 가장 싸게 확인한다.

- 시간 x 동안 처리 가능한 사람 수를 합산한다.
- 최소 간격 x를 유지하려면 제거해야 할 바위 수를 센다.
- 용량 x로 필요한 그룹/일 수가 제한 이하인지 센다.

합산 값이 이미 목표를 넘으면 조기 종료해 큰 수 계산과 시간을 줄일 수 있다.

## 이 폴더의 추천 학습 순서

1. `01_12982_예산`: 정렬+누적합에서 최대 지원 개수 경계를 찾는다. 그리디 풀이와 비교한다.
2. `02_43238_입국심사`: 시간 x에서 처리 가능한 사람 수로 최소 True를 찾는다.
3. `03_43236_징검다리`: 최소 간격 x를 만들기 위한 제거 수로 최대 True를 찾는다.

예산 문제는 이분탐색 없이도 풀 수 있다. 같은 답을 선형 그리디와 누적합+이분탐색으로
구해 “이분탐색이 가능하다”와 “이분탐색이 꼭 필요하다”의 차이를 익힌다.

## 복잡도 판단

탐색 범위 크기를 R, 판정 비용을 C라고 하면 `O(C log R)`이다. 입국심사는
심사관 n명을 매 판정마다 보므로 `O(n log(max_time))`이다. 값이 10억이어도
로그는 약 30회뿐이다.

## 자주 틀리는 이유

- `check`의 True/False 방향과 경계 갱신이 반대다.
- hi를 실제 답보다 작게 잡는다.
- 최소값 템플릿으로 최대값을 찾거나 그 반대를 한다.
- 중간값 편향이 없어 무한 루프가 난다.
- 출발점/도착점을 거리 계산에 포함하지 않는다.
- “정확히 n개 제거”와 “n개 이하 제거 가능” 판정을 혼동한다.
- 합계가 매우 커질 수 있는데 다른 언어에서 정수 오버플로를 놓친다.

## 디버깅 방법

작은 입력에서 모든 후보 x의 `check(x)`를 출력해 실제로 단조 배열인지 본다.

```text
x:        1 2 3 4 5 6
feasible: T T T F F F
```

루프마다 `(lo, mid, hi, check(mid))`를 출력하고 답이 구간 안에 남는지 확인한다.
무한 반복은 길이 2인 구간으로 재현한다.

## 효율적인 훈련법

- 최소 True와 최대 True 템플릿을 빈 파일에서 각각 3분 내 작성한다.
- 동일 문제를 반열린 구간 `[lo, hi)` 템플릿으로도 풀어 불변식 차이를 이해한다.
- 느린 전수 후보 풀이를 만들어 작은 랜덤 입력에서 결과를 비교한다.
- 문제 10개에서 코드는 쓰지 않고 답 후보, 구간, 단조성, 판정 비용만 적는다.

### 확장 문제 주제

- 공유기 설치·나무 자르기·랜선 자르기
- 최소 용량·최소 일수
- LIS의 `bisect_left`
- 실수 답 이분탐색과 반복 횟수/오차
- 병렬 처리 시간과 생산량
