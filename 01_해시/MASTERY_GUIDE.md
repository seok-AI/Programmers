# 해시 마스터 가이드

## 이 유형의 본질

해시는 “이 값을 전에 봤는가?”, “몇 번 나왔는가?”, “이 키에 대응하는 정보는
무엇인가?”를 반복해서 묻는 문제에서 선형 탐색을 제거하는 도구다. 핵심은 딕셔너리
문법이 아니라 **문제를 키와 값으로 번역하는 능력**이다.

마스터 기준은 다음과 같다.

- 리스트를 중첩 순회하려는 순간 역방향 매핑을 떠올린다.
- 중복 존재 여부와 등장 횟수 문제를 구분한다.
- 키 설계, 갱신 시점, 삭제 조건을 불변식으로 설명한다.
- 평균 `O(1)`이라는 성질과 최종 전체 복잡도를 구분해 말한다.

## 문제에서 포착할 신호

- 이름, ID, 문자열처럼 값 자체로 대상을 찾아야 한다.
- 두 목록의 차이, 빈도, 중복, 종류 수를 구한다.
- “현재 순위”, “마지막 위치”, “그룹별 합계”를 계속 갱신한다.
- 원소가 최대 100,000~1,000,000개라 이중 반복이 불가능하다.
- 같은 키가 여러 번 등장하며 순서보다 개수가 중요하다.

반대로 정렬 후 한 번의 선형 탐색으로 관계가 더 단순해지거나, 범위가 매우 작은
정수라 배열 카운팅이 더 적절할 수도 있다. 해시를 보았다고 무조건 `dict`부터 만들지
말고 키 범위와 필요한 연산을 먼저 본다.

## 사고 절차

1. 반복해서 찾는 대상에 밑줄을 긋는다.
2. “무엇을 알면 한 번에 답할 수 있는가?”를 값으로 정한다.
3. 중복을 무시하면 `set`, 개수가 필요하면 `Counter`/`dict`, 추가 정보가 필요하면
   일반 `dict`를 고른다.
4. 한 입력을 처리한 직후 딕셔너리가 나타내는 의미를 문장으로 쓴다.
5. 조회 전에 갱신할지, 조회 후 갱신할지 작은 중복 예제로 검증한다.

예를 들어 순위 교환 문제의 불변식은 “`position[name]`과 `players[position]`이 항상
서로 역함수 관계다”처럼 두 자료구조의 일관성으로 표현한다.

## 대표 패턴

### 빈도표

```python
from collections import Counter

counts = Counter(items)
for item in updates:
    counts[item] -= 1
    if counts[item] == 0:
        del counts[item]
```

### 값에서 위치로 가는 역방향 인덱스

```python
position = {value: index for index, value in enumerate(values)}

def swap(i, j):
    left, right = values[i], values[j]
    values[i], values[j] = right, left
    position[left], position[right] = j, i
```

### 그룹 집계

```python
from collections import defaultdict

total = defaultdict(int)
members = defaultdict(list)
for key, score, index in records:
    total[key] += score
    members[key].append((score, index))
```

## 복잡도 판단

- n개 원소를 한 번씩 조회·갱신하면 평균 `O(n)`이다.
- 그룹 안에서 다시 정렬하면 전체는 보통 `O(n log n)`이다.
- 딕셔너리에 큰 리스트를 값으로 저장하면 공간은 `O(n)`이다.
- 문자열 키의 해시 비용은 문자열 길이에 비례할 수 있으므로 긴 문자열을 반복해서
  자르는 구현은 별도 비용이 생긴다.

## 이 폴더의 추천 학습 순서

1. `01_1845_폰켓몬`: 집합과 선택 상한을 분리한다.
2. `02_42576_완주하지_못한_선수`: 중복이 있는 두 빈도표의 차이를 익힌다.
3. `03_178871_달리기_경주`: 양방향 매핑의 동시 갱신을 연습한다.
4. `04_42577_전화번호_목록`: 해시 접근과 정렬 접근을 모두 비교한다.
5. `05_42578_의상`: 그룹별 선택 수를 곱하는 조합 원리를 연결한다.
6. `06_42579_베스트앨범`: 집계, 그룹화, 다중 정렬 기준을 결합한다.

각 문제를 푼 뒤 같은 입력에 대해 정렬 풀이가 가능한지, 가능하다면 시간·공간
차이가 무엇인지 반드시 비교한다.

## 자주 틀리는 이유

- `set`을 사용해 중복 개수 정보를 잃는다.
- 없는 키 조회와 값이 0인 키를 혼동한다.
- 원본 배열만 바꾸고 역방향 인덱스를 갱신하지 않는다.
- 딕셔너리 순서에 우연히 의존한다.
- 그룹별 정렬 동률 조건을 빠뜨린다.
- 값이 아니라 인덱스가 정체성인 문제에서 같은 값을 한 대상으로 합친다.

## 디버깅 체크리스트

- 같은 값이 두 번, 세 번 들어온 최소 예제를 만들었는가?
- 빈도가 0이 된 키를 남겨도 의미가 변하지 않는가?
- 두 매핑이 모든 갱신 후 서로 일치하는가?
- 키가 없을 때 기본값이 0, 빈 리스트, 오류 중 무엇이어야 하는가?
- 반환 순서가 해시 순서가 아니라 명시된 정렬 기준을 따르는가?

## 효율적인 훈련법

### 1회차

문제마다 `key → value`를 종이에 한 줄로 적고 구현한다. 통과보다 모델링 문장의
정확성을 본다.

### 2회차

`Counter`, `defaultdict`, 일반 `dict`를 각각 사용해 보고 가장 명확한 버전을 고른다.
라이브러리 사용 이유를 설명하지 못하면 직접 딕셔너리로 다시 작성한다.

### 3회차

해시 풀이와 정렬 풀이를 모두 작성하고 n이 커질 때 어느 쪽이 유리한지 측정한다.

### 확장 문제 주제

- 아나그램 그룹화
- 두 수의 합과 보수 조회
- 가장 긴 연속 수열
- 좌표/문자열 상태 빈도
- LRU 캐시의 해시+연결 구조
